# 2026-11-18: Bringing a new association onto the platform (epic E13)

A record of a planning session with the coding agent (Claude Code CLI). Documentation only.

## 1. How we got here
- The owner preferred small tasks that need no deep involvement and postponed the setup wizard
  (local backlog L-9), which touches many mechanisms at once.
- The owner then asked for a staged plan of onboarding a new association, to discuss.
- The agent checked the code first: a building, apartments and meters are created only by the
  demo seed; `create-chairman` needs exactly one building; months open by themselves; invitations,
  documents, the register lookup and the chat switch (off by default) exist.

## 2. The plan the agent proposed
- Stage 0, once: a real installation without demo mode or seed, backups off the VPS, the
  installation marker in the database.
- Stage 1: a new installation by the operator, then `create-building` and `create-chairman`.
- Stage 2 in two steps: first an operator import from a filled template (cheap, no new screens),
  later the in-app setup wizard with the register's apartment list.
- Stages 3-6: the team, residents, the first month as a pilot, running administration.

## 3. Decisions of the owner
- The general plan is accepted and becomes its own epic, E13 "Rollout".
- E-mail (docs/BACKLOG.md B-8) waits; people get in through links handed over by a person.
- The owner considered nginx for the hostnames. The agent recommended keeping the existing Caddy
  edge: it already issues and renews certificates and holds the upload limits and timeouts, a new
  installation is one site block, and `sslip.io` hostnames need no registration. The page records
  Caddy; the owner can still revisit it.
